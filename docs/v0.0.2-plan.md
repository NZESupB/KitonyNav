# KitonyNav v0.0.2 开发计划

状态：v0.0.2 第一版已开始实施，配置 API、外观和基础采集已接入；本机探针闭环与发布验收待完成。
日期：2026-09-11。基线：`b261aa9`（v0.0.1），开发分支：`dev`。
配套文档：[技术框架与接口草案](./v0.0.2-architecture.md)。

## 1. 版本目标与已确认边界

把当前展示型导航站升级为可配置、能区分真实数据来源的个人导航工具，同时修复主题、侧栏和图标一致性问题。

- 本计划定义 v0.0.2 的交付边界；当前分支已实现第一版配置、外观和采集能力，计划中标为待补的项目仍未完成。
- 用户已确认：“本地”指访问网页的设备；真实 TCP 检测可以配合本机探针。远端 Go 服务测得的延迟不能作为访客设备的延迟。
- 沿用 React、TypeScript、TanStack Query、Motion、Go 和 SQLite；主运行形态仍是 Go/Docker，自托管数据继续持久化。
- 配置的服务、订阅、收藏夹和站点标识由单人后台管理；主题选择、时钟 DIY 覆盖值、探针绑定属于当前设备。站点可提供外观默认值。
- Sites 保留静态预览/打包兼容性，本版不同时重写一套 Worker 动态后端。
- 天气真实采集、多用户系统、告警推送、监控历史图表、任意脚本插件、网站整体重设计不在这 9 项需求的实施范围内。

当前实现进度：服务和订阅管理已接入 Go/SQLite，HTTP/TCP 服务检查、RSS/Atom、GitHub Releases 和 YouTube Feed 已有基础适配；主题、折叠侧栏、统一图标、favicon、时钟预设、浏览器连通性和 WebRTC/IP 面板已接入；独立 allowlist 本机 TCP 探针已提供。Statuspage 专用解析、探针配对闭环、IP 归属 provider、跨浏览器验证和发布验收仍未完成。

## 3. 关键产品与技术取舍

### 3.1 服务健康与本机连通性分开

“GitHub 官方服务正常”和“我的设备能够连接 github.com:443”回答不同问题。一个服务行应同时容纳服务来源的健康结果和本机探针的连接结果，不能合并成一个误导性的绿点。

普通网页不能对任意端口发起原始 TCP 连接；Chrome Direct Sockets 属于 Isolated Web Apps 的能力，不适合作为当前普通导航页的跨浏览器实现。因此建议将可选 Go 探针作为 v0.0.2 真实 tcping 的组成部分。[Chrome 官方说明](https://developer.chrome.com/docs/iwa/direct-sockets)

无探针时提供有限的浏览器 HTTP 检测。能读取响应时显示 HTTP 响应情况与请求耗时；CORS、证书、浏览器策略、混合内容等错误可能无法细分，统一显示“浏览器无法确认”。`no-cors` 的 opaque 响应无法读取状态码，不能等同于服务正常或 TCP 延迟。[MDN Fetch 说明](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)

### 3.2 本机探针采用主动连接

建议探针复用 Go 工具链，运行在访问设备上，主动通过 HTTPS 向 KitonyNav Go API 领取检测任务并回传结果。网页通过本站 API 读取与当前设备配对的结果，避免把浏览器直连 localhost 的跨源、证书和网络权限兼容性作为主路径。

首个技术验证必须覆盖：远端 KitonyNav + 本机探针 + 当前浏览器配对、断连恢复、两个设备结果隔离。只有这一链路证明可用后，才扩展到完整监控界面。无探针设备仍可正常使用导航、订阅和外观功能。

### 3.3 WebRTC IP 不等于归属地，也不保证是真实出口

WebRTC 负责收集可用 ICE 候选地址；STUN 映射地址、HTTP 请求出口、VPN/代理出口可能不同。TURN relay 地址不能标记为用户公网 IP，mDNS 名称不作为 IP 查询。归属地/运营商需要独立的 IP 数据提供商，且只能作为网络归属参考。[MDN 候选类型](https://developer.mozilla.org/en-US/docs/Web/API/RTCIceCandidate/type)、[IETF WebRTC IP 处理规范](https://www.rfc-editor.org/rfc/rfc8828.html)

默认展示 HTTP 观测地址；WebRTC/STUN 在后台自动采集，不提供“查询归属”或“启用 WebRTC”页面控件。无需摄像头或麦克风权限。供应商不可用时仍显示已获取的 IP，不虚构城市、ISP 或“真实 IP”。

### 3.4 功能界面采用有限扩展

- 后台沿用现有 `/admin`，增加“服务监控”“动态订阅”“外观”“网络与探针”分区，站点设置承载品牌默认值。
- 首页状态/动态面板的配置入口定位到对应分区；未登录时回到相应登录流程。
- 主题仅顶部一个入口。时钟外观在设置中编辑，不另造一个大型首页时钟区域。
- 先使用现有图标库和已有闪电品牌标记；统一资源引用，不以品牌一致性修复为由重新设计 logo。
- 分类/链接自定义图标先支持内置 key 与受校验图片 URL；任意 SVG 文本、执行脚本和上传存储系统不作为本版前置条件。

## 5. 回归与验收矩阵

沿用项目现有验证命令，实施时给对应模块补正式测试。当前没有配置格式检查命令或自动化浏览器测试框架；不把它们写成“已通过”，也不为了名称增加工具链。

| 范围 | 自动化回归重点 | 浏览器 / 集成验收重点 |
| --- | --- | --- |
| 数据兼容 | v0.0.1 数据库 fixture；新库/旧库/重复迁移/事务失败；原分类、链接、设置不丢失。 | 老用户启动新版后仍能看到并编辑原数据。 |
| 监控与探针 | 本地 fake TCP listener 成功、拒绝、超时、DNS 失败；过期 job 拒收、缓存失效、鉴权、配对撤销、设备隔离。 | 远端部署与本机设备路径可证实；禁用或断开探针后不显示上一台设备的绿色状态。 |
| 外部请求 | 本地 `httptest` 模拟重定向、DNS 重绑定、私网目标、过大响应、超时、状态页解析错误。 | 官方状态和本机不可达可以同时正确显示；HTTP 故障与 TCP 可达不混淆。 |
| 订阅 | RSS/Atom 编码与日期、GitHub/YouTube 样本、稳定去重、ETag/304、429、停用/删除、旧缓存保留。 | 新建/编辑/排序/停用/删除即时反映；源失败能定位，动态页筛选到具体源。 |
